# Review pack — TypeScript / JavaScript

Detect: `tsconfig.json`, `*.ts` / `*.tsx` / `*.js` / `*.mjs` files, or a `package.json` in the changed paths (any runtime: Node, Bun, Deno, browser).

Applies on top of core.md; the project's own rules and its tsconfig/lint settings win. Check `strict`, `noUncheckedIndexedAccess` and the lint config before judging a typing finding.

## Critical
1. **Prototype pollution or unsafe merge of untrusted objects.** Mechanism: `Object.assign`, spread into a shared object, a deep-merge helper or `obj[key][sub] = value` with keys taken from user input lets `__proto__` / `constructor` keys modify every object in the process, which can flip authorization flags. Spot: dynamic key assignment from request data or parsed JSON. Correct: allow-list keys, use `Map`, or `Object.create(null)`; check whether the project's merge helper already blocks these keys.

## High
2. **Floating promise / missing await.** Mechanism: an async call whose result is neither awaited, returned nor `.catch`-ed runs detached; its failure becomes an unhandled rejection and the caller proceeds before the write finished. Spot: async function calls as bare statements, `async` callbacks passed to `forEach` (never awaited), `return` missing in a `.then` chain, `await` missing before a call inside `try` (so the `catch` never fires). Correct: `await`, `Promise.all` over `map`, or an explicit `void` with a catch for intentional fire-and-forget.
3. **`as` cast or non-null `!` that hides a real null.** Mechanism: `x as Foo`, `x!` or `<Foo>x` on data from the network, storage, `find()`, `Map.get`, DB results or env silences the compiler while the value can still be `undefined` at runtime, giving a crash far from the cause. Spot: a cast on external data with no validation before it. Correct: narrow with a check, or parse with the project's schema validator (zod, valibot, io-ts or equivalent) instead of asserting.
4. **Unchecked index access and `find` results.** Mechanism: `arr[0]`, `record[key]`, `str.split(",")[1]`, `match[1]` are typed as defined but are `undefined` on empty or short input; `.find()` result used without a check. Spot: property access straight off an index or `find` on input-dependent data. Correct: guard for length/presence first.
5. **`JSON.parse` or `as` on untrusted input without validation.** Mechanism: `JSON.parse` throws on malformed text and returns `any`; unvalidated shapes (wrong types, extra keys, arrays instead of objects) flow into logic and storage. Spot: `JSON.parse` of request bodies, queue messages, localStorage, webhook payloads, env values, outside a try/catch and a schema parse. Correct: try/catch plus the project's validator.
6. **Loose equality and truthiness bugs on values that can be 0, "" or false.** Mechanism: `==` coerces (`"0" == 0`, `null == undefined`), and `if (count)`, `value || default`, `if (!id)` treat a valid `0`, `""` or `false` as missing; `||` defaults overwrite legitimate zeros. Spot: defaults and presence checks on numbers, booleans, and optional strings. Correct: `===`, `??`, `?.`, and explicit `=== undefined` checks. Do not report `x == null` if the project uses it deliberately.
7. **Date pitfalls.** Mechanism: `new Date("2024-05-01")` parses as UTC but `new Date("2024-05-01T00:00")` as local time; `getMonth()` is zero-based; `setDate`/`setMonth` mutate in place and mutate shared instances; adding `24*3600*1000` ms breaks across DST; `toISOString().slice(0,10)` yields the UTC date, not the user's. Spot: date arithmetic, day-bucketing, and comparisons of date-only strings. Correct: the project's date library, or explicit UTC math; clone before mutating.
8. **Numeric parsing and arithmetic traps.** Mechanism: `parseInt(x)` without radix or on `"12abc"` returns 12; `Number("")` is `0`; `NaN` is not equal to itself and passes `typeof === "number"`; ids above 2^53 lose precision as `number`; `Array.prototype.sort()` with no comparator sorts numbers as strings. Spot: parsing of query params, ids from external APIs, sorts of numeric arrays. Correct: validate with `Number.isFinite`/`Number.isInteger`, keep big ids as strings or `bigint`, pass a comparator.
9. **Mutation of shared or input state.** Mechanism: `sort`, `reverse`, `splice`, `push` on an array received as an argument, a cached value, a module-level constant or a default parameter object mutates it for every other caller; shallow spread copies still share nested objects. Spot: in-place array methods on props, args, store state or imported constants. Correct: copy first (`toSorted`, `[...a]`, `structuredClone`).
10. **Stale or error-prone async control flow.** Mechanism: `Promise.all` rejects on the first failure while the other operations keep running and their results are lost; unbounded `Promise.all` over a large list opens thousands of concurrent calls; a `setTimeout`/`setInterval` callback that throws is uncaught; a `try/finally` missing around a lock or loading flag leaves it stuck. Spot: those constructs in a changed block. Correct: `allSettled` where partial results matter, a concurrency limit (the project's helper or p-limit style), try/finally for state flags.
11. **Error handling that loses the error.** Mechanism: `catch (e)` then `throw new Error("failed")` drops the cause and stack; `e.message` used on a value that may not be an `Error` (anything can be thrown); `.catch(() => {})` hides a failed write. Spot: rewrapped errors without `cause`, and unnarrowed `e`. Correct: pass `{ cause }`, narrow with `instanceof Error`.

## Medium
12. **Enum and union pitfalls that cause bugs.** Mechanism: numeric `enum` values are reassigned or reordered and persisted numbers change meaning; `const enum` breaks across isolated-module builds; a `switch` over a union with no `default`/exhaustiveness check silently ignores a newly added member. Spot: persisted or serialized enums with changed members; non-exhaustive switches over a type this change extended. Correct: string unions or string enums, `never` exhaustiveness check.
13. **Module-level mutable state and import side effects.** Mechanism: a module-scope `let`, cache or array shared across requests leaks data between users in a server process; code that runs at import time (connecting, reading env, starting timers) runs in tests and in every consumer. Spot: top-level mutable state keyed by nothing, or top-level calls with effects. Correct: scope state per request/instance, initialize lazily or inside an explicit start function.
14. **Type-level lies at boundaries.** Mechanism: a function typed to return `Promise<T>` that actually returns `T | undefined`, an interface hand-written to describe an API response that does not match the real shape, or `Partial<T>` / optional fields widened to dodge an error. Spot: signatures changed in the diff versus what the body really returns. Correct: make the type match the runtime or validate at the boundary.

## Do not report
- `any`, `unknown` casts, `@ts-expect-error` or non-null `!` where the project's lint config allows them, or in test files and fixtures.
- Missing types or "cannot find module" for generated, gitignored or workspace packages absent from the checkout.
- Enums vs unions as a style preference, when nothing persisted or serialized is affected.
- `==` null checks used deliberately, and `for...of` vs `forEach` taste, when no async or ordering bug results.
- Anything `tsc`, ESLint (`no-floating-promises`, `eqeqeq`) or the formatter already enforces in CI.
