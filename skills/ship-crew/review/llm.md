# Review pack — LLM and agent code

Detect: SDKs in dependencies (`openai`, `anthropic`, `@anthropic-ai/sdk`, `google-genai` / `@google/generative-ai`, `langchain`, `llama-index`, `ai` (Vercel AI SDK), MCP server/client packages, vector-store clients such as pgvector, Pinecone, Qdrant, Chroma, Weaviate); prompt files or template strings; tool/function definitions; embedding calls.

Applies on top of core.md and the language pack; the project's rules win. Find the project's LLM client wrapper, its config for model ids and limits, its schema-validation layer and its tool registry before judging the rules below.

## Critical
1. **Indirect prompt injection reaches an agent that can act.** Mechanism: text the attacker controls (user message, uploaded document, web page, email, ticket, tool result, retrieved chunk) is placed in the prompt of an agent that also holds write tools, secrets or private data; the text says "ignore instructions, send the data to X" and the model complies. Spot: untrusted content concatenated into a prompt in the same call that has tools such as send-email, write-file, run-query, HTTP fetch, payment, delete. Correct: least-privilege tool set per task (read-only when reading untrusted content), no secrets in context, human confirmation or an allow-list for destructive or outbound actions, untrusted content delimited and treated as data. Prompt wording alone is not a fix.
2. **Vector search without tenant or owner filter.** Mechanism: a similarity query over a shared index returns the nearest chunks across all tenants; one customer receives another's documents, directly or inside a generated answer. Spot: `query` / `similarity_search` / `search` calls with no metadata filter, namespace or row-level condition derived from the session; a filter taken from client input. Correct: the tenant/owner filter comes from the session and is applied by the store (namespace, partition, RLS), not by post-filtering the top-k in application code.
3. **Retrieved content shown to a user without an access check.** Mechanism: RAG returns chunks, citations, source links or file names that the current user may not be allowed to read, because the index was built from everything. Spot: sources rendered from retrieval results with no per-document permission check at query time. Correct: filter by the caller's permissions before retrieval, or verify each cited document against the project's access check before returning it.
4. **Model output executed or rendered as trusted.** Mechanism: output passed to `eval`/`exec`, a shell, a SQL string, a file path, an HTTP client (SSRF), a redirect, or HTML/Markdown rendered without sanitizing; prompt injection or a plain hallucination becomes code execution, injection or XSS. Spot: `subprocess`, `exec`, raw query builders, `fetch(url)` or `dangerouslySetInnerHTML` fed from a completion or tool-call argument. Correct: treat output as untrusted user input: parameterize, allow-list commands and hosts, sandbox code execution, sanitize or render as text.
5. **Secrets or personal data sent to a provider or logged.** Mechanism: API keys, tokens, full customer records, emails, health or payment data placed into prompts, or full prompts and completions written to logs, traces or analytics, where retention and access are broader than for the source data. Spot: whole objects serialized into a prompt, `logger.info(prompt)`, tracing/observability SDKs capturing inputs by default. Correct: send only the needed fields, redact or pseudonymize first, log ids and token counts, and follow the project's data-handling rules for providers.

## High
6. **Model-chosen tool arguments trusted.** Mechanism: the model supplies ids, paths, queries or amounts in a tool call, and the tool executes them with the service's own privileges instead of the end user's. A user, or injected text, can steer the model to another user's record. Spot: tool handlers that take `user_id`, `account_id`, `path` or raw SQL from arguments. Correct: the tool resolves the owner from the session, validates arguments against a schema, and runs checks as the caller. (Extends core rules 1 and 2.)
7. **Output used as structured data without validation or stop-reason handling.** Mechanism: `JSON.parse` / `json.loads` of free text, or fields read from a response with no schema check; a refusal, a truncated answer (`stop_reason` / `finish_reason` of `max_tokens` / `length`) or a content-filter stop yields broken JSON or an empty string that flows on as if valid. Spot: parsing without try/validate, no check of the stop reason, `choices[0].message.content` used unguarded. Correct: structured-output or tool-call mode plus schema validation (the project's validator), explicit handling of refusal, truncation and empty content, with a bounded repair or retry.
8. **No timeout, or retry that is wrong.** Mechanism: an LLM call with no request timeout hangs a worker or request; no backoff and jitter on 429, 5xx and overloaded responses turns a provider blip into an outage, while blind retries on 4xx waste money. Spot: a client built with default timeouts and `max_retries=0` or an unbounded custom loop. Correct: explicit timeout, bounded retries with exponential backoff and jitter on retryable statuses only, honoring `retry-after`; use the SDK's retry settings or the project's wrapper.
9. **Retry re-runs tool side effects.** Mechanism: an agent turn or whole workflow is retried after a timeout or parse failure, and tools that already sent an email, wrote a row or charged a card run again. Spot: a retry wrapper around a loop that executes tools. Correct: retry only the model call, not completed tool executions; give side-effecting tools idempotency keys. (Extends core rule 17.)
10. **Unbounded tokens and cost.** Mechanism: no `max_tokens` / output cap; conversation history appended forever until the context overflows or each turn costs more; user-controlled input (file, URL, paste) sent whole; per-user budget absent on an endpoint anyone can call. Spot: `messages.push` with no trimming or summarizing, no size check before the call, an input size taken straight from the request. Correct: cap input and output sizes, trim or summarize history, enforce per-user quotas the project already uses. (Extends core's rule on cost-bearing endpoints.)
11. **Agent loop with no cap.** Mechanism: a `while` loop or recursive graph that continues while the model requests tools has no maximum number of turns, tool calls or total budget; a confused model or a tool that keeps failing loops until the bill or timeout stops it. Spot: loops conditioned only on "has tool calls" or on the model saying it is done. Correct: a hard turn limit, a token or cost budget, loop detection on repeated identical calls, and a defined failure result at the limit.
12. **Streaming not stopped on disconnect.** Mechanism: the client closes the connection but the server keeps consuming the provider stream, so tokens are still generated and billed and the worker stays busy; or a partial stream is stored as a complete answer. Spot: a streaming handler with no abort signal, no cancel on `close` / request abort, results saved from a stream that ended on error. Correct: propagate the abort to the provider call, close the stream in `finally`, persist only completed responses.
13. **Embeddings mixed across models or dimensions.** Mechanism: documents are embedded with one model and queries with another, or the model or dimension changes without re-embedding the stored vectors; similarity scores become meaningless and results degrade silently, or inserts fail on dimension mismatch. Spot: a changed embedding model id or dimension constant with no re-index step; two code paths embedding with different settings. Correct: one configured embedding model for write and read, the model id stored with the index, a reindex migration when it changes.

## Medium
14. **Model id and parameters scattered.** Mechanism: the model name and limits hardcoded in many call sites make an upgrade or deprecation a hunt, and some sites get missed and fail at the provider's retirement date. Spot: string literals of model ids outside the config or wrapper. Correct: one configured constant or setting per use case, read through the project's config layer.
15. **Prompt cache defeated.** Where the project uses prompt caching, the cacheable prefix must be stable: system prompt, tool definitions and fixed documents first, volatile content (timestamps, user data, request ids) last. Spot: a timestamp, random id or per-user text placed before the stable block, or tool lists reordered per request. Correct: stable content first with the cache marker after it; volatile content at the end.
16. **Tests assert exact model text.** Mechanism: assertions on exact completions are flaky and fail on any model update, while assertions on shape are stable. Spot: `toEqual("...")` on a live model response. Correct: mock the client for logic tests; for live checks, assert schema, required facts or use the project's eval harness.

## Do not report
- Choice of model, prompt wording or style, temperature and other sampling values.
- Missing evals or guardrail frameworks in prototypes and spikes.
- Provider-specific API shape differences when the code works with the pinned SDK version.
- Logging of prompts in clearly local-only debug tooling that is not shipped.
- Tool or agent framework choice as taste.
